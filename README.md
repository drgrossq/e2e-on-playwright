# SauceDemo: E2E-тесты на Playwright и TypeScript

Учебный проект для QA-портфолио: **15 сценариев** для [SauceDemo](https://www.saucedemo.com).
Покрыты вход, каталог, корзина, оформление заказа и меню. Основной браузер — Chromium.

Тесты проверяют пользовательский интерфейс реального демо-стенда, без подмены ответов.
В проекте есть Page Object Model, изолированные браузерные контексты, сохранение авторизации,
статический анализ и workflow GitHub Actions. Границы покрытия и приоритеты описаны
в [тест-плане](docs/TEST_PLAN.md).

## Стек технологий

| ----------------------------------------------------- | ------------------------------------------------------------------------------------------- |

| Playwright Test                                       | Chromium, фикстуры, assertions и HTML-отчёты                                                |
| TypeScript, strict                                    | Проверка типов тестов и Page Object                                                         |
| ESLint 9, typescript-eslint, eslint-plugin-playwright | В том числе поиск забытых `await`, запрет `test.only`, `test.skip` и фиксированных задержек |
| Prettier                                              | Форматирование                                                                              |
| GitHub Actions                                        | Статические проверки, E2E и артефакты                                                       |

Точные версии зависимостей зафиксированы в `package-lock.json`; для установки используется `npm ci`.

## Установка и запуск

1. Установить Node.js 22 (не ниже 22.14) и открыть терминал в корне проекта.
2. Установить зависимости и Chromium:

   ```sh
   npm ci
   npx playwright install chromium
   ```

   В Linux для системных библиотек: `npx playwright install --with-deps chromium`.
   Команда `npx playwright install` также подходит, но загрузит и дополнительные браузеры.

3. Проверить код и запустить тесты:

   ```sh
   npm run check
   npm test
   ```

4. Открыть отчёт:

   ```sh
   npm run report
   ```

Полный прогон содержит **16 проверок: 15 сценариев + 1 подготовка авторизации**.
Для работы нужен доступ к внешнему стенду. Локальный сервер приложения не требуется.

По умолчанию используется `https://www.saucedemo.com`. Для совместимой копии стенда можно
создать `.env` из `.env.example` и изменить `BASE_URL`. В PowerShell: `Copy-Item .env.example .env`;
в Bash: `cp .env.example .env`. Без `.env` проект тоже работает.

Если PowerShell блокирует `npm.ps1`, использовать `npm.cmd` и `npx.cmd` вместо `npm` и `npx`.

## Архитектурные решения

**Page Object Model.** Классы содержат локаторы и действия, проверки результата находятся
в тестах. Локаторы создаются в конструкторе: не требуется менять семантику полей TypeScript.
Общий BasePage не нужен для пяти небольших объектов. Каталог и детали товара пока объединены,
поскольку используют одинаковые атрибуты; при расширении карточки её можно выделить.

**Фикстуры.** `test` создаёт POM на стандартной странице Playwright.
`authenticatedTest` добавляет автоматическую фикстуру `authenticatedPage`: открывает каталог,
проверяет авторизацию и пустую корзину. Smoke и негативные проверки входа используют обычный `test`.

**Авторизация и изоляция.** Setup входит через UI и сохраняет `storageState`. Каждый тест получает
собственный контекст с копией состояния, не общую страницу. Корзина SauceDemo хранится на стороне
браузера, поэтому один демо-аккаунт подходит для параллельного запуска. Для системы с общими заказами
или корзиной на сервере потребуются отдельные аккаунты/данные и очистка.
Smoke и негативные auth-сценарии явно задают пустое состояние.
Такой подход описан в [документации Playwright](https://playwright.dev/docs/auth).

**Локаторы и ожидания.** `getByTestId` настроен на атрибут `data-test`.
Исключение — кнопки открытия/закрытия меню: используются роль и доступное имя.
Проверки DOM используют `await expect(locator)`, включая массивы текстов.
Нет `waitForTimeout`, `force: true` и проверок мгновенных снимков через `allTextContents`.
Причина — [автоматические повторные проверки Playwright](https://playwright.dev/docs/test-assertions).

**Ожидаемые значения.** Данные каталога заданы отдельно от интерфейса. Суммы вычисляются в центах:
для Backpack и Bike Light сумма товаров — 39.98 USD, налог 8% — 3.20 USD, итог — 43.18 USD.
Налог 8% — принятое правило демо-стенда, а не универсальное правило интернет-магазинов.
Для A–Z сначала устанавливается обратный порядок: тест должен обнаруживать неработающую сортировку.

## Отчётность и CI

Workflow запускается на push в `main`/`master`, на pull request и вручную.
Порядок: `npm ci` → статические проверки → установка Chromium → тесты → артефакты.

В CI включено до двух повторных попыток. Это снижает влияние временных сетевых сбоев внешнего SauceDemo. Тест, успешно прошедший при retry, отмечается как flaky в Playwright Report, но не приводит к падению workflow. Если все попытки завершаются ошибкой, CI падает.
Поведение параметра описано в [документации Playwright](https://playwright.dev/docs/api/class-testconfig#test-config-fail-on-flaky-tests).

HTML-отчёт хранится в артефакте `playwright-report` 14 дней, диагностика — в `test-results` 7 дней.
Загрузка выполняется и при падении тестов, если файлы успели появиться; отменённый прогон не загружает их.
Скриншоты сохраняются при падении, видео сохраняются для неуспешных попыток.
Trace по умолчанию записывается на первом повторе, поэтому локальное падение без retries не создаёт trace.

Для диагностики конкретного теста с trace с первой попытки:

```sh
npm test -- --grep CHK-02 --trace on
```

Открыть trace можно из HTML-отчёта. Каждая новая команда запуска тестов заменяет локальный отчёт.

## Ограничения

Это выборочная функциональная регрессия учебного магазина. Набор не проверяет реальные оплату,
доставку, backend API, БД, нагрузку или полную доступность. Прохождение не означает отсутствие
дефектов во всём приложении. Изменения и недоступность внешнего стенда могут вызвать падения.
